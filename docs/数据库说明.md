# 数据库说明

本文档用于说明 `LeadBot` 项目的数据库选型、建库方式、初始化方式、表结构组成以及开发/测试/生产环境建议。

---

## 1. 数据库选型

当前项目后端推荐使用以下数据库方案：

- **开发环境**：H2（可选）
- **测试 / 生产环境**：MySQL 8.x

推荐正式环境统一使用：

- **MySQL 8.0+**
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_general_ci`

---

## 2. 数据库名称

建议数据库名称为：

```sql
leadbot
```

---

## 3. 建库方式

可先在 MySQL 中执行以下 SQL：

```sql
CREATE DATABASE IF NOT EXISTS leadbot
DEFAULT CHARACTER SET utf8mb4
DEFAULT COLLATE utf8mb4_general_ci;
```

---

## 4. 数据库连接配置示例

后端连接 MySQL 的典型配置如下：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/leadbot?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
    username: root
    password: 123456
```

> 生产环境请不要直接使用默认密码，请根据实际环境调整账号和密码。

---

## 5. 初始化方式说明

当前项目支持两种数据库初始化方式：

### 方式 A：Flyway 迁移（推荐）
适合：
- 测试环境
- 生产环境
- 多人协作开发
- 持续迭代升级

推荐目录：

```text
src/main/resources/db/migration/
├─ V1__init.sql
└─ V2__seed_data.sql
```

说明：
- `V1__init.sql`：负责建表
- `V2__seed_data.sql`：负责初始化基础数据

### 方式 B：直接执行 SQL 文件
适合：
- 本地快速初始化
- 单独交付数据库脚本
- 手工建库测试

推荐目录：

```text
database/sql/
├─ 01_schema.sql
└─ 02_seed.sql
```

说明：
- `01_schema.sql`：建表脚本
- `02_seed.sql`：初始化演示数据脚本

## 6. 表结构概览

系统用户表

用途：
- 登录认证
- 角色控制
- 用户基本资料

主要字段：
- `id`
- `username`
- `password`
- `name`
- `role`
- `avatar`
- `created_at`
- `updated_at`

---

### 2）`lead`
客户线索表

用途：
- 存储客户线索基本信息
- 管理客户状态、等级、来源、标签、备注

主要字段：
- `id`
- `name`
- `company`
- `industry`
- `phone`
- `level`
- `status`
- `source`
- `tags`
- `note`
- `last_follow`
- `created_at`
- `updated_at`

---

### 3）`follow_log`

- `desc`

## 7. 审计字段说明

多数业务表都包含以下两个标准字段：

- `created_at`：创建时间
- `updated_at`：更新时间

作用：
- 便于数据追踪
- 便于排序
- 便于后期做审计和统计分析

后端已支持 JPA 审计能力，建议统一保留。

## 8. 默认角色说明

当前系统内置 3 种角色：

- `ADMIN`
- `MANAGER`
- `USER`

建议含义如下：

### `ADMIN`
管理员，拥有全部权限：
- 用户管理
- 成员管理
- 渠道管理
- 规则管理
- 全部业务查看与操作

### `MANAGER`
经理，拥有业务管理权限：
- 线索管理
- 跟进管理
- 任务管理
- 聊天
- 渠道与规则查看/更新
- 数据报表查看

### `USER`
普通成员，拥有基础业务权限：
- 线索查看/编辑
- 跟进记录
- 任务
- 聊天
- 个人信息

## 10. 索引建议

当前建议至少建立以下索引：

### 在线索表 `lead`
- `idx_lead_name`
- `idx_lead_company`
- `idx_lead_level`
- `idx_lead_status`

### 在跟进日志表 `follow_log`
- `idx_follow_log_lead_id`

### 在操作日志表 `operate_log`
- `idx_operate_module`
- `idx_operate_action`

后续如果数据量变大，可继续增加：
- `lead(industry)`
- `lead(source)`
- `follow_log(created_at)`
- `task_item(done)`

## 16. 常见问题

### 1）数据库连接失败
请检查：
- MySQL 是否启动
- 数据库名是否正确
- 用户名密码是否正确
- 端口是否开放

### 2）Flyway 启动失败
请检查：
- 旧表结构是否与迁移脚本冲突
- 是否曾经手工建表但未同步迁移历史
- 是否重复执行了建表 SQL

### 3）中文乱码
请确保：
- 数据库字符集使用 `utf8mb4`
- JDBC URL 带有 `characterEncoding=utf8`
- 表和字段均使用默认 UTF-8 编码

### 4）默认账号无法登录
请检查：
- 用户是否初始化成功
- 密码是否已被修改
- 后端是否采用 BCrypt 校验
- SQL 中的密码是否与初始化逻辑一致
