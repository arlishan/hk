# 前端工程说明

本文档用于说明 `leadbot-h5/frontend/source/leadbot-vue` 前端工程的结构、运行方式、模块职责与后续扩展建议。

---

## 1. 工程定位

该前端工程是 `LeadBot` 智能获客系统的移动端风格后台前端，采用：

- Vue 3
- Vite
- Vue Router
- Axios

当前工程具备以下特点：

- 支持登录鉴权
- 支持角色权限控制
- 支持 mock / real 双模式切换
- 支持线索分页、搜索、筛选
- 支持团队、渠道、规则等管理能力
- 支持统一的 loading / empty / error 状态展示
- 适合作为 MVP、演示版或正式项目起点

## 6. mock / real 模式说明

系统支持两种模式：

### 6.1 mock 模式
适合：
- 本地快速演示
- 后端未完成时联调
- UI 先行验证

特点：
- 接口由本地模拟层返回
- 数据存储在 LocalStorage
- 不依赖真实后端服务

### 6.2 real 模式
适合：
- 前后端联调
- 测试环境
- 生产环境

特点：
- 请求真实 Spring Boot 后端
- 通过 axios 发送 HTTP 请求
- token 自动注入请求头

### 6.3 切换方式
通过环境变量控制：

```env
VITE_API_MODE=mock
```

或：

```env
VITE_API_MODE=real
```

## 7. 核心模块职责说明

---

### 7.1 `router/`
负责页面路由与前端访问控制。

主要职责：
- 登录守卫
- 无权限页面跳转
- 页面路径管理

典型页面：
- `/login`
- `/dashboard`
- `/leads`
- `/chat`
- `/tasks`
- `/profile`
- `/reports`
- `/team`

---

### 7.2 `store/`
负责轻量状态与本地存储封装。

当前主要承担：
- token 保存与读取
- 用户信息保存与读取
- mock 数据缓存
- 主题状态保存

说明：
当前未使用 Pinia / Vuex，而是使用轻量函数式封装，适合当前项目规模。

后续若业务继续扩大，建议升级为：
- Pinia

---

### 7.3 `api/`
负责所有接口调用。

结构分为三层：

#### 第一层：`request.js`
统一封装 axios：
- baseURL
- 超时
- token 注入
- 响应拦截
- 401 / 403 处理

#### 第二层：`modules/`
按模块拆分真实接口：
- `auth.js`
- `leads.js`
- `tasks.js`
- `chat.js`
- `logs.js`
- `members.js`
- `channels.js`
- `rules.js`

#### 第三层：`mock.js`
统一适配层：
- mock 模式返回本地数据
- real 模式转发到真实接口

这样做的好处是：
- 页面层不关心真实/模拟模式
- 后续替换后端时只需改 API 层

## 8. 权限控制说明

前端权限控制分为两层：

### 8.1 路由层权限
由 `router/index.js` 控制：
- 未登录跳转登录页
- 无权限跳转 `403` 页面

### 8.2 按钮 / 菜单层权限
由 `utils/permission.js` 控制：
- 是否显示报表页
- 是否显示团队成员页
- 是否显示渠道和规则配置
- 是否允许删除客户

当前角色定义：

- `ADMIN`
- `MANAGER`
- `USER`

## 11. 登录与鉴权说明

### 登录流程
1. 用户在登录页输入账号密码
2. 调用 `/auth/login`
3. 获取 token 与用户信息
4. token 保存到本地
5. 用户信息保存到本地
6. 跳转工作台

### 鉴权方式
所有受保护接口通过请求头传递：

```http
Authorization: Bearer <token>
```

### 失效处理
- `401`：自动清理登录状态并跳转登录页
- `403`：跳转无权限页

```json

  "code": 0,
  "message": "ok",
  "success": true,
  "data": {}
```

```json

  "code": 0,
  "message": "ok",
  "success": true,
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
```

## 16. 常见问题

### 1）前端启动报错
检查：
- Node 版本是否过低
- 是否已执行 `npm install`

### 2）登录后跳回登录页
检查：
- token 是否成功保存
- 后端是否正确返回 token
- 请求是否带 `Authorization`

### 3）页面没有数据
检查：
- 当前是否处于 mock 模式
- 后端接口是否返回成功
- 返回结构是否符合约定

### 4）权限菜单不对
检查：
- `/auth/profile` 返回的 `role`
- `permission.js` 判断逻辑
- 路由守卫逻辑
