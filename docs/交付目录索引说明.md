# 交付目录索引说明

本文档用于说明 `leadbot-h5` 交付目录下各文件夹和文件的作用，方便开发、测试、部署、运维和交付人员快速定位所需内容。

---

## 1. 交付根目录说明

当前交付目录建议结构如下：

```text
leadbot-h5/
├─ README.md
├─ docs/
├─ frontend/
├─ backend/
├─ database/
├─ deploy/
└─ postman/
```

各目录说明如下：

- `README.md`：项目总说明文档
- `docs/`：交付文档、说明文档
- `frontend/`：前端源码及构建相关内容
- `backend/`：后端源码及运行相关内容
- `database/`：数据库脚本与迁移脚本
- `deploy/`：部署配置与部署脚本
- `postman/`：接口测试集合与环境变量文件

## 4. frontend 目录说明

### 目录路径
```text
frontend/
```

### 作用
用于保存前端相关交付内容。

### 建议结构
```text
frontend/
├─ source/
│  └─ leadbot-vue/
└─ dist/
```

---

### 4.1 `frontend/source/leadbot-vue/`
前端源码目录，包含完整 Vue 3 + Vite 工程。

#### 主要用途
- 二次开发
- 联调
- 构建生产包
- 代码审查

#### 主要内容
通常包括：
- `package.json`
- `vite.config.js`
- `index.html`
- `src/`
- `.env.development`
- `.env.production`

---

### 4.2 `frontend/dist/`
前端生产构建产物目录。

#### 作用
- 可直接部署到 Nginx
- 用于正式环境或测试环境静态托管

#### 获取方式
在前端源码目录执行：
```bash
npm install
npm run build
```

---

## 5. backend 目录说明

### 目录路径
```text
backend/
```

### 作用
用于保存后端源码、运行产物和配置文件。

### 建议结构
```text
backend/
├─ source/
│  └─ leadbot-backend/
├─ jar/
│  └─ leadbot-backend-1.2.0.jar
└─ config/
```

---

### 5.1 `backend/source/leadbot-backend/`
后端完整源码目录，基于 Spring Boot 3。

#### 主要用途
- 二次开发
- 本地调试
- 构建 Jar
- 维护接口逻辑

#### 主要模块
- 认证模块
- 用户模块
- 线索模块
- 跟进日志模块
- 任务模块
- 聊天模块
- 团队成员模块
- 渠道模块
- 规则模块
- 公共组件、配置、安全模块

---

### 5.2 `backend/jar/`
后端可运行 Jar 包目录。

#### 作用
- 用于快速部署
- 运维直接运行
- 测试环境启动

#### 获取方式
在后端源码目录执行：
```bash
mvn clean package -DskipTests
```

---

### 5.3 `backend/config/`
后端外置配置目录。

#### 作用
- 放生产环境配置
- 不修改 Jar 包即可调整数据库、端口、日志等参数

#### 建议内容
- `application-prod.yml`
- `logback-spring.xml`（如有）

---

## 6. database 目录说明

### 目录路径
```text
database/
```

### 作用
用于保存数据库相关脚本。

### 建议结构
```text
database/
├─ sql/
│  ├─ 01_schema.sql
│  └─ 02_seed.sql
└─ flyway/
```

---

### 6.1 `database/sql/`
数据库手工初始化脚本目录。

#### 文件说明

##### `01_schema.sql`
- 建表脚本
- 索引脚本
- 适合手工初始化数据库结构

##### `02_seed.sql`
- 演示数据脚本
- 默认账号
- 线索、任务、成员、渠道、规则等初始化数据

---

### 6.2 `database/flyway/`
Flyway 迁移脚本目录。

#### 作用
- 标准化数据库迁移
- 适合持续迭代升级
- 适合测试/生产环境自动迁移

#### 典型文件
- `V1__init.sql`
- `V2__seed_data.sql`

---

## 7. deploy 目录说明

### 目录路径
```text
deploy/
```

### 作用
用于保存与部署相关的文件和脚本。

### 建议结构
```text
deploy/
├─ leadbot.conf
├─ docker-compose.yml
├─ nginx/
├─ docker/
├─ scripts/
└─ env/
```

---

### 7.1 `leadbot.conf`
Nginx 配置文件。

#### 作用
- 托管前端静态文件
- 代理 `/api/` 到后端
- 代理 Swagger 文档

---

### 7.2 `docker-compose.yml`
容器化一键部署文件。

#### 作用
- 同时启动 MySQL、后端、前端
- 用于标准化交付或测试环境快速部署

---

### 7.3 `deploy/nginx/`
可选目录，用于统一存放多个 Nginx 配置文件。

---

### 7.4 `deploy/docker/`
可选目录，用于存放：
- 前端 Dockerfile
- 后端 Dockerfile
- 容器配置补充文件

---

### 7.5 `deploy/scripts/`
部署脚本目录。

#### 建议内容
- `deploy-frontend.sh`
- `deploy-backend.sh`
- `start-backend.bat`
- `build-frontend.bat`

#### 作用
- 简化部署流程
- 统一运维执行方式

---

### 7.6 `deploy/env/`
环境变量模板目录。

#### 建议内容
- `.env.development.example`
- `.env.production.example`

#### 作用
- 给交付方一个标准配置模板
- 避免直接暴露真实敏感配置

## 8. postman 目录说明

### 目录路径
```text
postman/
```

用于保存接口测试集合和环境变量。

### 建议内容
```text
postman/
```

接口测试集合文件。

#### 作用
- 快速导入 Postman
- 方便联调和测试
- 便于交付给测试或第三方开发人员

### 8.2 `LeadBot.postman_environment.json`
Postman 环境变量文件。

#### 作用
- 管理 `baseUrl`
- 管理 `token`
- 管理测试账号

## 11. 交付时的建议说明

交付时建议明确告知接收方：

1. 默认账号仅用于测试与演示
2. 生产环境必须修改默认密码
3. 生产环境必须替换 JWT 密钥
4. 推荐数据库使用 MySQL 8
5. 推荐部署方式为 Nginx + Spring Boot + MySQL
6. Docker Compose 适合快速拉起测试环境
