# 后端工程说明

本文档用于说明 `LeadBot` 后端工程的定位、结构、依赖、运行方式、模块划分与扩展建议，便于开发、维护、交付和二次开发。

---

## 1. 项目简介

`LeadBot` 后端是一个基于 **Spring Boot 3** 构建的业务服务端，主要为前端提供：

- 登录认证
- 用户资料
- 线索管理
- 跟进记录
- 任务管理
- AI 聊天
- 团队成员管理
- 渠道预算管理
- 机器人规则配置
- 权限控制
- 操作日志

该工程当前已经具备“**开发版后端骨架**”的完整基础，适合作为：

- 内部测试系统后端
- 智能获客系统 MVP 后端
- 前后端联调基础服务
- 后续正式产品化开发起点

## 3. 工程职责

后端的主要职责包括：

1. 提供前端所需 REST 接口
2. 实现登录认证和权限校验
3. 持久化业务数据
4. 提供统一错误处理
5. 记录关键操作日志
6. 支持角色区分（ADMIN / MANAGER / USER）
7. 支持分页、筛选、关键字搜索
8. 提供可演进的数据结构与迁移脚本

## 8. 鉴权与权限控制

### 8.1 登录方式
使用 JWT Token：

1. 调用 `/auth/login`
2. 返回 token
3. 前端后续请求通过 `Authorization: Bearer <token>` 传递

### 8.2 后端认证方式
当前通过 JWT 过滤器实现：
- 从请求头提取 token
- 解析用户名
- 查用户
- 将登录用户写入请求上下文

### 8.3 角色权限
系统内置三个角色：

- `ADMIN`
- `MANAGER`
- `USER`

权限示例：
- `/members/**` → ADMIN
- `/channels/**` → ADMIN / MANAGER
- `/rules/**` → ADMIN / MANAGER
- `/leads/**` → 已登录用户
- `/tasks/**` → 已登录用户
- `/chats/**` → 已登录用户

## 9. 密码策略

当前系统使用：

- `BCryptPasswordEncoder`

这意味着：
- 数据库中存的是加密后的密码
- 登录时使用明文密码进行匹配
- 不能直接比对字符串

开发默认账号密码可以在初始化时由代码生成加密值。

建议：
- 生产环境必须修改默认密码
- 生产环境不应保留演示账号
- 后续可以扩展密码复杂度策略

## 11. MapStruct 用途

当前引入 MapStruct 的目标是：

- 实体 `Entity`
- 请求对象 `DTO`
- 返回对象 `VO`

三层分离，避免：
- 直接暴露实体
- Controller 返回字段混乱
- 后续扩展展示字段困难

例如在线索模块中：
- `Lead` → 数据库存储实体
- `LeadCreateRequest` / `LeadUpdateRequest` → 请求对象
- `LeadVO` → 返回给前端的展示对象

## 16. 推荐开发规范

建议开发时遵循以下约定：

### 命名规范
- 控制器：`XxxController`
- 服务：`XxxService`
- 仓库：`XxxRepository`
- 请求对象：`XxxRequest`
- 返回对象：`XxxVO`

### 分层原则
- Controller：接收请求、返回响应
- Service：业务逻辑
- Repository：数据库访问
- DTO / VO：输入输出结构
- Entity：数据库实体

### 返回格式统一
所有接口统一返回：
- `ApiResponse`

### 错误处理统一
所有异常统一交给：
- `GlobalExceptionHandler`
